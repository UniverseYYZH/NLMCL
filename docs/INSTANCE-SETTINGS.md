# 实例设置（M6-A）

## 存哪里

`<mc>/versions/<版本>/nlcl-settings.json`

**为什么按版本目录存，而不是全局一个文件**：

1. 用户复制/移动版本文件夹时，设置跟着走
2. 删掉版本时设置一起消失，不留孤儿配置
3. 不同版本可以有不同的内存与 Java（这是常态：1.12.2 要 Java 8，1.21 要 Java 21）

## 字段

| 字段 | 说明 |
|---|---|
| `memoryMb` | 分配内存，默认 2048 |
| `javaPath` | 指定 Java；为空表示自动挑已探测到的最高版本 |
| `extraArguments` | 额外游戏参数，按空白分词 |
| `serverAddress` | 直连地址（当前界面未暴露） |

## 行为

- **选中版本时自动加载**该实例的设置到界面
- **保存**按钮写回文件（不做自动保存——避免用户改到一半就被写盘）
- **启动时**：`javaPath` 有值就用它，否则自动挑；`memoryMb` 进 `LaunchRequest.MaximumMemoryMb`

## 容错

- 文件不存在 → 默认设置
- 文件是坏的 JSON → 默认设置（**不能让坏配置拦住启动**）
- 不写 `javaPath` 就不会覆盖自动选择

## 仍未做

- 界面没有暴露 `serverAddress`（后端已支持）
- 没有"恢复默认"按钮
- 没有 Java 版本与 MC 版本匹配的校验（用户填错 Java 7 会启动失败，靠崩溃检测提示）
